PerfectOutfit — Progress Log

2026-05-26
- Fixed issue #3 ("Location name does not change"). After navigating Home -> Settings ->
  Home, selecting a different city in the Home dropdown sometimes had no visible effect.
  Root cause: an uncancellable FusedLocationProvider lastLocation callback (plus a slow
  reverse-geocode) from a "Current location" request could resolve late and unconditionally
  overwrite selectedLocationName, snapping the displayed city back. A redundant dual-trigger
  design (explicit setter + DataStore-driven combine collector) fetched and wrote the name
  twice with no cancellation of stale in-flight work, which made the post-navigation timing
  reproducible.
  Fix (HomeViewModel.kt):
    * Added a locationGeneration token; current-location callbacks capture it at request
      time and re-check after the geocode, so a stale result can no longer overwrite a
      newer selection.
    * combine collector now uses distinctUntilChanged().collectLatest so stale fetches are
      cancelled and unrelated DataStore writes don't re-fire it.
    * Location setters now only write the optimistic name + DataStore; the collector is the
      single fetch path (removed the duplicate racing fetch).
    * Fixed the "Current Location"/"Current location" casing mismatch that broke the
      startsWith() checks in HomeScreen.

2026-06-04
- Fixed issue #1 ("Change threshold for extra UV protection from 3 to 5").
  The UvInfoCard (suggesting sunglasses, UV sleeves, and sun lotion) was shown whenever
  the selected hour's UV index was >= 3. Changed the threshold to >= 5 per the issue.
  Change: HomeScreen.kt line 438, `currentWeather.uvIndex >= 3` → `>= 5`.

- Implemented issue #2 ("Import / Backup functionality").
  Favorite locations were the only database entity missing from the JSON export/import.
  Also added the "yymmdd_" date prefix to the suggested export filename.
  Changes:
    * ExportImportManager.kt: added ExportFavoriteLocation data class; ExportData gains
      a `favoriteLocations` field (default emptyList for backwards-compatible import of
      old backups); exportToJson() now fetches all saved locations; importFromJson() clears
      and restores locations after the other entities.
    * LocationRepository.kt: added deleteAll() and insertAll() helpers used by the manager.
    * SettingsScreen.kt: export button now generates filename with yyMMdd_ prefix
      (e.g. 260604_perfect_outfit_data.json) using java.time.LocalDate.

2026-07-27
- Added quick-response rating buttons ("Too cold" / "Perfect" / "Too hot") to the
  post-workout rating reminder notification, so a rating can be logged without opening
  the app.
  Design (via /grill-me interview): buttons added to the existing reminder notification
  (NotificationHelper.kt) rather than a new one; tapping a button cancels the notification,
  saves the rating (last-write-wins, no-op if the entry was deleted), and shows a brief
  confirmation Toast.
  Changes:
    * NotificationHelper.kt: showRatingNotification() now adds three NotificationCompat.Action
      buttons, each a PendingIntent.getBroadcast targeting RateOutfitActionReceiver with a
      distinct data URI (perfectoutfit-rate://<entryId>/<rating>) so the three actions and the
      existing content intent never collide.
    * RateOutfitActionReceiver.kt (new): @AndroidEntryPoint BroadcastReceiver, exported=false,
      registered in AndroidManifest.xml. Validates the intent via RatingActionValidator, then
      uses goAsync() + a coroutine to delegate to RatingActionHandler before calling finish().
    * RatingActionHandler.kt (new): the actual async logic (cancel notification, call
      OutfitRepository.rateEntry(), show toast) factored out of the receiver into a plain
      injectable class. Kept separate because coroutines launched directly inside the
      Hilt-transformed receiver hung under Robolectric's sandboxed classloader in testing;
      delegating to a plain class sidesteps that and is independently unit-testable.
    * RatingActionValidator.kt (new): pure entryId/rating validation, no Android dependencies.
    * strings.xml: added rating_saved_toast.
    * Added Robolectric + androidx.test:core as test dependencies (build.gradle.kts,
      libs.versions.toml) to unit-test the receiver and handler.
